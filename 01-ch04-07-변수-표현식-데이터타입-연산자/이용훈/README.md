# 모던 자바스크립트 Deep Dive — 4~7장 정리

> 4장 변수 / 5장 표현식과 문 / 6장 데이터 타입 / 7장 연산자

---

## 4장. 변수

### 1) 변수의 생명주기 3단계
자바스크립트 엔진은 변수를 다음 순서로 처리한다.

1. **선언 단계**: 변수 이름을 실행 컨텍스트의 변수 객체(스코프)에 등록
2. **초기화 단계**: 메모리에 공간을 확보하고 `undefined`로 초기화
3. **할당 단계**: 실제 값을 대입

`var`는 선언과 초기화가 동시에 일어나고, `let`/`const`는 선언과 초기화가 분리되어 있다. 이 분리 때문에 TDZ가 생긴다.

```js
console.log(a); // undefined (선언+초기화가 끝난 상태)
var a = 1;

console.log(b); // ReferenceError (TDZ 구간)
let b = 1;
```

### 2) 호이스팅의 실체
"호이스팅 = 코드가 끌어올려진다"는 비유는 이해를 돕기 위한 것일 뿐, 실제로는 코드가 물리적으로 이동하지 않는다. 실행 컨텍스트가 생성될 때 렉시컬 환경(Lexical Environment)에 변수 식별자가 먼저 등록되기 때문에 마치 끌어올려진 것처럼 동작하는 것이다.

```js
function foo() {
  console.log(x); // undefined, ReferenceError 아님
  var x = 10;
}
foo();
```

함수 선언문도 호이스팅된다 (함수 전체가 메모리에 등록됨). 함수 표현식은 변수 호이스팅 규칙을 따른다.

```js
sayHi(); // 정상 동작 - 함수 선언문
function sayHi() { console.log('hi'); }

sayHello(); // TypeError: sayHello is not a function
var sayHello = function () { console.log('hello'); };
```

### 3) var가 문제인 3가지 이유
| 문제 | 설명 |
|---|---|
| 함수 스코프만 지원 | 블록(`if`, `for` 등) 밖에서도 변수 접근 가능 → 스코프 오염 |
| 재선언 허용 | 같은 이름으로 다시 `var`를 선언해도 에러 없이 덮어씀 |
| 선언 전 접근 시 undefined | 버그가 조용히 발생, 디버깅 어려움 |

```js
if (true) {
  var x = 1;
}
console.log(x); // 1 (블록 스코프 무시됨)

var y = 1;
var y = 2; // 에러 없음, 의도치 않은 덮어쓰기 가능
```

### 4) let, const와 TDZ
```js
console.log(temp); // ReferenceError
let temp = 'a';
```
TDZ는 실수를 조용히 넘어가지 않고 즉시 에러를 던진다는 점에서 안전장치로 볼 수 있다. `var`의 `undefined` 반환은 버그를 숨기지만, TDZ의 `ReferenceError`는 버그를 즉시 드러낸다.

### 5) 함수 레벨 스코프 vs 블록 레벨 스코프
- **함수 레벨 스코프**: 함수 몸체만을 스코프로 인정. `var`가 여기 해당 — 함수 밖에서 선언하면 전역 변수, 함수 안이면 지역 변수. `if`, `for` 같은 블록은 스코프로 취급하지 않는다.
- **블록 레벨 스코프**: 모든 코드 블록(함수, if, for, while, try/catch 등)을 스코프로 인정. `let`, `const`가 해당.

```js
var x = 1;
if (true) {
  var x = 10; // 같은 전역 변수 x를 덮어씀 (함수 레벨 스코프)
}
console.log(x); // 10

let y = 1;
if (true) {
  let y = 10; // 블록 안의 별개 변수
}
console.log(y); // 1
```

`for`문 안에서 `var`로 카운터 변수를 선언했을 때 콜백/클로저에서 의도치 않게 마지막 값을 공유하는 버그가 대표적인 사례다.

```js
// var 카운터
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0); // 3, 3, 3
}

// let 카운터 - 각 반복마다 새로운 블록 스코프 생성
for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log(j), 0); // 0, 1, 2
}
```

### 6) 스코프 체인과 변수 검색
스코프가 계층적으로 연결된 것을 스코프 체인이라 하며, 변수를 참조할 때는 현재 스코프에서 시작해 상위 스코프로 순차 검색한다 (렉시컬 스코프). 실행 컨텍스트가 생성될 때 이 스코프 체인이 함께 구성되고, 각 실행 컨텍스트의 렉시컬 환경에는 그 스코프에서 선언된 식별자들이 등록된다. 이게 앞서 말한 "호이스팅 시 식별자가 먼저 등록된다"는 설명의 실체다.

### 7) 할당과 재할당, 그리고 메모리/가비지 컬렉션
변수에 값을 할당하면 자바스크립트 엔진은 새로운 메모리 공간을 확보해 값을 저장하고, 변수는 그 메모리 주소를 참조한다. 재할당은 기존 메모리 값을 변경하는 게 아니라, 새 값을 위한 메모리 공간을 새로 확보하고 변수가 참조하는 주소를 바꾸는 것이다.

```js
let x = 1; // 메모리에 1을 저장, x가 그 주소를 가리킴
x = 2;     // 메모리에 2를 새로 저장, x가 이제 이 주소를 가리킴
           // 기존 1이 저장된 메모리는 더 이상 참조되지 않음
```

더 이상 어떤 변수도 참조하지 않는 메모리는 가비지 컬렉터(GC)가 자동으로 해제한다. 자바스크립트는 개발자가 직접 메모리를 해제하지 않고, 엔진(V8 등)이 도달 가능성(reachability)을 기준으로 판단해 더 이상 도달할 수 없는 메모리를 회수한다. `const`로 원시값을 선언해도 재할당이 안 될 뿐이지 메모리 관리 방식 자체가 달라지는 건 아니다.

### 예상 면접 질문
**Q. var와 let/const의 차이를 스코프와 호이스팅 관점에서 설명해보세요.**
> var는 함수 레벨 스코프를 가지며 선언과 동시에 undefined로 초기화되어, 선언 전에 접근해도 에러 없이 undefined가 반환된다. let/const는 블록 레벨 스코프를 가지며 선언과 초기화가 분리되어 있어(TDZ), 선언 전에 접근하면 ReferenceError가 발생한다. 또한 var는 재선언이 허용되지만 let/const는 허용되지 않는다.

## 5장. 표현식과 문

### 1) 값, 표현식, 문의 관계
- **값(value)**: 표현식이 평가되어 만들어진 최종 결과
- **표현식(expression)**: 값으로 평가될 수 있는 코드. 리터럴, 변수, 연산자 조합, 함수 호출 등이 모두 표현식
- **문(statement)**: 프로그램 실행의 최소 단위. 여러 표현식과 키워드로 구성되며 세미콜론으로 끝남

```js
// 표현식 (값으로 평가됨)
10 + 20
'hello'
x
foo()

// 문 (표현식을 포함하지만 그 자체는 실행 단위)
var x = 10 + 20;
if (x > 0) { console.log(x); }
```

### 2) 표현식인 문 vs 표현식이 아닌 문
할당문은 문이면서 동시에 표현식이기도 하다. 그래서 다음처럼 체이닝이 가능하다.

```js
var x, y;
x = y = 10; // y = 10 이 표현식으로 평가되어 x에 다시 할당됨
console.log(x, y); // 10 10
```

반면 변수 선언문(`var x;`)은 표현식이 아니므로 값으로 사용할 수 없다.

```js
console.log(var x = 10); // SyntaxError
```

### 3) 완료 값(completion value)
크롬 개발자 도구 콘솔에서 문을 실행하면 완료 값이 출력되는데, 이는 표현식이 아닌 문에도 편의상 부여되는 값일 뿐 실제 코드에서 사용할 수 있는 값은 아니다.

### 4) 표현식/문 구분이 실제로 쓰이는 곳
이 구분을 알아야 화살표 함수의 암묵적 반환이 왜 가능한지 설명된다: `() => value`는 `value`가 표현식이기 때문에 바로 반환값이 되는 것이다. JSX의 `{ }` 안에는 표현식만 들어갈 수 있는 것도 같은 이유다.

```jsx
// 안됨 - if는 문이라 표현식 자리에 못 들어감
{ if (cond) { <A /> } }

// 됨 - 삼항 연산자는 표현식
{ cond ? <A /> : <B /> }
```

### 예상 면접 질문
**Q. 표현식과 문의 차이를 설명하고, 할당문이 특이한 이유를 말해보세요.**
> 표현식은 평가되어 값을 만들어내는 코드이고, 문은 프로그램 실행의 최소 단위다. 대부분의 문은 표현식이 아니지만, 할당문은 예외적으로 문이면서 동시에 표현식이기도 하다. 그래서 `x = y = 10`처럼 할당 결과를 다시 다른 변수에 할당하는 체이닝이 가능하다.

## 6장. 데이터 타입

### 1) 원시 타입 vs 객체 타입
| 구분 | 종류 | 특징 |
|---|---|---|
| 원시 타입 | number, string, boolean, undefined, null, symbol, bigint | 값 자체가 저장, 불변(immutable), 값에 의한 전달(pass by value) |
| 객체 타입 | object (배열, 함수, 정규식 등 포함) | 참조 값이 저장, 가변(mutable), 참조에 의한 전달(pass by reference) |

```js
let a = 10;
let b = a;
b = 20;
console.log(a); // 10 (원시 타입은 값이 복사됨)

let obj1 = { x: 10 };
let obj2 = obj1;
obj2.x = 20;
console.log(obj1.x); // 20 (객체 타입은 참조가 복사됨)
```

### 2) 동적 타이핑
자바스크립트 변수는 선언이 아니라 할당 시점에 타입이 결정된다. 재할당하면 타입도 동적으로 바뀐다.

```js
var foo = 'string';
console.log(typeof foo); // string
foo = 123;
console.log(typeof foo); // number
```

`typeof` 연산자는 변수의 타입이 아니라 변수에 할당된 값의 타입을 반환한다. 엄밀히 말하면 변수 자체는 타입을 갖지 않는다.

### 3) typeof의 함정
```js
typeof undefined        // "undefined"
typeof null             // "object" (자바스크립트의 유명한 사양 버그)
typeof function(){}      // "function"
typeof []                // "object"
typeof NaN               // "number"
```
`typeof null`이 `"object"`인 건 초기 자바스크립트 설계 버그로, 하위 호환성 때문에 지금까지 수정되지 않고 남아있다. `null` 여부를 체크할 때는 `typeof` 대신 `=== null`로 비교해야 한다.

### 4) 템플릿 리터럴
```js
const first = 'Ung-mo';
const last = 'Lee';

// ES5
console.log('My name is ' + first + ' ' + last + '.');

// ES6
console.log(`My name is ${first} ${last}.`);
```

### 예상 면접 질문
**Q. 원시 타입과 객체 타입의 차이를 메모리 관점에서 설명해보세요.**
> 원시 타입은 값 자체가 변수에 저장되고 불변이라, 변수 간 대입 시 값이 그대로 복사된다(pass by value). 객체 타입은 데이터가 저장된 메모리 주소(참조값)가 변수에 저장되고 가변이라, 변수 간 대입 시 참조값이 복사되어 같은 객체를 가리키게 된다(pass by reference). 그래서 한 변수를 통해 객체 프로퍼티를 변경하면 그 객체를 참조하는 다른 변수에서도 변경이 반영된다.

## 7장. 연산자

### 1) 단축 평가 (short-circuit evaluation)
`&&`, `||`는 좌항만으로 결과가 결정되면 우항을 평가하지 않고 즉시 반환한다.

```js
'Cat' && 'Dog'   // 'Dog' (둘 다 truthy면 마지막 값)
false && 'Dog'   // false (좌항이 falsy면 좌항 반환)
'Cat' || 'Dog'   // 'Cat' (좌항이 truthy면 좌항 반환)
false || 'Dog'   // 'Dog'
```

React에서 흔한 패턴:
```jsx
{isLoggedIn && <Welcome />}
```
`isLoggedIn`이 falsy(`false`, `0`, `''`, `null`, `undefined`)면 그 값 자체가 렌더링된다. `count`가 `0`일 때 `{count && <Component />}`는 화면에 `0`이 그대로 찍히는 흔한 버그가 되므로, `{count > 0 && <Component />}`처럼 boolean으로 변환해서 써야 안전하다.

### 2) 옵셔널 체이닝(`?.`)과 null 병합 연산자(`??`)
```js
const user = { name: 'yonghun' };
console.log(user.address?.city); // undefined (에러 없이 안전하게 접근)

const value = 0;
console.log(value || '기본값');  // '기본값' (0이 falsy라 의도치 않게 대체됨)
console.log(value ?? '기본값');  // 0 (null/undefined일 때만 대체됨)
```
`||`는 falsy 값 전체를 대체 대상으로 삼지만, `??`는 `null`/`undefined`만 체크한다는 차이가 실무에서 자주 헷갈리는 포인트다.

### 3) 암묵적 타입 변환 (Type Coercion)
```js
1 + '2'       // '12' (문자열 변환)
1 + true      // 2   (true → 1)
1 + null      // 1   (null → 0)
1 + undefined // NaN (undefined는 변환 불가)

'1' == 1      // true  (암묵적 타입 변환 후 비교)
'1' === 1     // false (타입까지 비교)
```

### 4) == vs === 비교표 (자주 헷갈리는 케이스)
| 비교 | `==` 결과 | 이유 |
|---|---|---|
| `null == undefined` | true | 둘 다 값 없음으로 취급 |
| `NaN == NaN` | false | NaN은 자기 자신과도 다름 (`Number.isNaN()`으로 체크해야 함) |
| `[] == false` | true | 배열→문자열→숫자 변환 체인 발생 |
| `'0' == false` | true | 둘 다 0으로 변환됨 |

### 예상 면접 질문
**Q. `||`와 `??`의 차이, 그리고 언제 `??`를 써야 하는지 설명해보세요.**
> `||`는 좌항이 falsy(`false`, `0`, `''`, `null`, `undefined`, `NaN`)면 무조건 우항을 반환한다. `??`는 좌항이 `null` 또는 `undefined`일 때만 우항을 반환한다. 그래서 숫자 `0`이나 빈 문자열처럼 "값은 있지만 falsy한" 데이터를 기본값으로 대체하고 싶지 않은 경우(예: 사용자가 입력한 수량 0)에는 `||` 대신 `??`를 써야 의도치 않은 대체를 막을 수 있다.
