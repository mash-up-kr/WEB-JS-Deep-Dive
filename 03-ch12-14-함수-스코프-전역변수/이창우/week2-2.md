# 모던 자바스크립트 Deep Dive 12~14장 정리

변수, 함수, 스코프, 전역 변수의 문제점을 중심으로 정리

## 12장. 함수

### 함수의 역할

함수는 입력을 받아 출력을 내보내는 일련의 과정이다. 자바스크립트의 클로저, 실행 컨텍스트, 객체 생성, 메서드, `this`, 프로토타입, 모듈화 같은 주요 개념은 함수와 밀접하게 연결된다.

자바스크립트에서 함수는 함수 리터럴로 생성되는 객체다. 일반 객체는 호출할 수 없지만 함수 객체는 호출할 수 있으며, 값처럼 변수에 할당하거나 프로퍼티·배열 요소로 사용할 수 있는 일급 객체다.

## 함수 정의 방식

### 함수 선언문

```js
function add(x, y) {
  return x + y;
}

add(2, 5); // 7
```

함수 선언문은 표현식이 아닌 문이지만, 함수 이름과 같은 식별자를 자바스크립트 엔진이 암묵적으로 만들어 함수 객체를 연결한다. 따라서 함수 이름이 아니라 식별자를 통해 함수를 호출한다.

```js
function foo() {
  console.log('foo');
}

foo(); // foo
```

함수 이름은 함수 몸체 내부에서 유효한 식별자이고, 외부에서는 엔진이 만든 식별자를 사용한다.

### 함수 표현식

```js
const add = function (x, y) {
  return x + y;
};

add(2, 5); // 7
```

함수 리터럴은 문맥에 따라 함수 선언문 또는 함수 표현식으로 해석된다.

```js
function foo() {
  console.log('foo');
}

(function bar() {
  console.log('bar');
});

foo(); // foo
// bar(); // ReferenceError: 함수 표현식의 이름 bar는 외부 식별자가 아님
```

`{}`가 코드 블록 또는 객체 리터럴로 해석될 수 있는 것처럼, 함수 리터럴도 단독으로 사용하면 선언문으로, 값이 필요한 문맥에서 사용하면 표현식으로 해석된다.

### 화살표 함수

```js
const add = (x, y) => x + y;
```

화살표 함수는 함수를 간결하게 정의하는 ES6 문법이다. 일반 함수와 `this` 바인딩, `prototype` 프로퍼티, `arguments` 객체 등의 동작이 다르므로 단순한 문법 축약으로만 이해하면 안 된다.

### 함수 정의 방식 비교

| 방식 | 특징 | 선언 전 접근 |
| --- | --- | --- |
| 함수 선언문 | 이름이 있는 함수를 선언하고 함수 객체를 즉시 연결 | 가능 |
| 함수 표현식 | 함수 객체를 만든 뒤 변수에 할당 | 할당 전에는 불가 |
| 화살표 함수 | 익명 함수를 간결하게 표현하며 일반 함수와 `this` 동작이 다름 | 할당 전에는 불가 |

함수의 동작 자체보다 **언제 생성되고 어떤 식별자로 접근하는지**가 세 방식의 주요 차이다.

## 함수 생성 시점과 호이스팅

함수 선언문과 함수 표현식은 생성·할당 시점이 다르다.

```js
console.log(add(2, 5)); // 7
// console.log(sub(2, 5)); // TypeError: sub는 undefined

function add(x, y) {
  return x + y;
}

var sub = function (x, y) {
  return x - y;
};
```

자바스크립트 엔진은 런타임 전에 선언을 처리한다.

| 정의 방식 | 런타임 전 식별자 상태 | 선언 전 호출 |
| --- | --- | --- |
| 함수 선언문 | 함수 객체가 연결됨 | 가능 |
| `var` 함수 표현식 | `undefined`로 초기화됨 | 불가 (`TypeError`) |
| `let`·`const` 함수 표현식 | 초기화 전 상태(TDZ) | 불가 (`ReferenceError`) |

함수 호이스팅은 함수 객체가 연결된 상태까지 준비한다는 점에서 `var` 변수 호이스팅과 다르다.

## 함수 호출

### 매개변수와 인수

함수를 호출하면 함수 실행 컨텍스트가 생성되고, 매개변수 바인딩이 함수 실행 환경에 만들어진다. 전달된 인수는 매개변수에 순서대로 연결되며, 대응하는 인수가 없으면 `undefined`가 된다.

```js
function add(a, b) {
  const result = a + b;
  return result;
}

add(10, 20); // 30
add(10); // NaN (b는 undefined)
```

실행 흐름은 다음과 같이 이해하면 된다.

```text
함수 호출
  ↓
함수 실행 컨텍스트 생성
  ↓
매개변수 바인딩 생성 및 인수 연결
  ↓
함수 본문 실행
  ↓
반환값 전달
```

명세의 세부 초기화 단계를 모두 외우기보다는, “호출 시 실행 컨텍스트에 매개변수가 바인딩되고, 인수가 없으면 `undefined`가 된다”로 이해하는 것이 실용적이다.

매개변수 개수에는 문법상 제한이 없지만, 함수는 하나의 일을 하도록 만들고 매개변수는 적게 유지하는 편이 의도를 파악하기 쉽다.

## 참조에 의한 전달과 외부 상태 변경

자바스크립트의 인수 전달은 항상 값에 의한 전달이다. 다만 객체 값에는 객체를 가리키는 참조가 들어 있으므로, 객체를 전달하면 같은 객체를 가리키는 참조 값이 복사된다.

```js
function changeScore(user) {
  user.score = 100;
}

const user = { score: 0 };
changeScore(user);
console.log(user.score); // 100
```

원시 값은 값 자체가 복사되므로 외부 변수에 영향을 주지 않지만, 객체는 내부 프로퍼티를 변경하면 외부 상태도 바뀐다. 이런 부수 효과는 추적하기 어려운 원인이 될 수 있다.

필요하다면 객체를 직접 변경하지 말고 복사본을 만들어 반환한다.

```js
function changeScore(user) {
  return { ...user, score: 100 };
}

const user = { score: 0 };
const changedUser = changeScore(user);
```

## 콜백 함수와 고차 함수

콜백 함수는 함수의 매개변수를 통해 다른 함수 내부로 전달되어 특정 시점에 호출되는 함수다. 콜백을 전달받아 실행하는 함수를 고차 함수라고 한다.

```js
function repeat(count, callback) {
  for (let i = 0; i < count; i += 1) {
    callback(i);
  }
}

repeat(3, (index) => console.log(index)); // 0, 1, 2
```

변하지 않는 공통 로직은 고차 함수에 두고, 달라지는 동작은 콜백으로 전달하면 로직을 재사용할 수 있다. 이벤트 리스너, 배열 메서드의 인수 등이 대표적인 활용 사례다.

## 순수 함수와 비순수 함수

| 구분 | 특징 |
| --- | --- |
| 순수 함수 | 같은 인수에 항상 같은 값을 반환하고 외부 상태를 읽거나 변경하지 않음 |
| 비순수 함수 | 외부 상태에 의존하거나 외부 상태를 변경함 |

```js
// 순수 함수
function add(a, b) {
  return a + b;
}

// 비순수 함수: 외부 변수 변경
let total = 0;
function increase(value) {
  total += value;
}
```

순수 함수는 결과를 예측하기 쉽고 테스트와 재사용에 유리하다. 객체를 다룰 때는 원본을 변경하지 않는 불변 처리 방식을 우선 고려한다.

### 12장 핵심 흐름

```text
함수 정의
  ├─ 선언문: 함수 호이스팅으로 선언 전 호출 가능
  ├─ 표현식: 변수 할당 이후 호출 가능
  └─ 화살표 함수: 간결한 문법, 일반 함수와 다른 this 동작
       ↓
함수 호출 → 실행 컨텍스트와 매개변수 생성
       ↓
인수 전달 → 원시 값은 값 복사, 객체는 참조 값 복사
       ↓
콜백 전달 → 공통 로직과 변경 로직 분리
       ↓
순수 함수 지향 → 외부 상태 변경 최소화
```

## 13장. 스코프

### 스코프란?

스코프는 **식별자가 유효한 범위**다. 변수나 함수의 이름을 어디까지 사용할 수 있는지를 결정하며, 같은 이름이 여러 개 있을 때 어떤 식별자를 참조할지도 결정한다. 이 과정을 식별자 결정이라고 한다.

```js
const x = '전역';

function outer() {
  const x = '지역';
  console.log(x); // 지역: 가장 가까운 지역 스코프의 x
}

outer();
console.log(x); // 전역
```

스코프는 함수를 호출한 위치가 아니라 함수를 **어디에 정의했는지**를 기준으로 결정된다. 코드가 작성된 위치와 주변 코드의 관계를 렉시컬 환경이라고 하며, 실행 컨텍스트는 이 환경을 바탕으로 코드를 평가하고 실행한다.

### 전역 스코프와 지역 스코프

- **전역 스코프**: 코드의 가장 바깥 영역. 전역 변수는 프로그램 어디서든 접근할 수 있다.
- **지역 스코프**: 함수 내부처럼 특정 영역에 생성되는 스코프. 지역 변수는 해당 스코프와 하위 스코프에서만 접근할 수 있다.

```js
const globalValue = '전역';

function showValue() {
  const localValue = '지역';
  console.log(globalValue); // 전역 변수 접근 가능
  console.log(localValue); // 지역 변수 접근 가능
}

showValue();
// console.log(localValue); // ReferenceError: 함수 밖에서는 접근 불가
```

### 스코프 체인

함수가 중첩되면 스코프도 계층적인 구조를 이룬다. 이 연결을 스코프 체인이라고 한다.

```js
const x = '전역';

function outer() {
  const y = 'outer';

  function inner() {
    const z = 'inner';
    console.log(z); // inner: 현재 스코프에서 찾음
    console.log(y); // outer: 상위 스코프에서 찾음
    console.log(x); // 전역: 계속 상위로 이동해 찾음
  }

  inner();
}

outer();
```

변수를 참조할 때 자바스크립트 엔진은 현재 스코프에서 검색을 시작한다. 찾지 못하면 상위 스코프로 이동하며, 전역 스코프까지 검색한 뒤에도 없으면 `ReferenceError`를 발생시킨다. 하위 스코프가 상위 스코프의 변수에 접근할 수 있는 이유도 이 검색 규칙 때문이다.

```text
inner 스코프
  ↓ 없으면
outer 스코프
  ↓ 없으면
전역 스코프
  ↓ 그래도 없으면
ReferenceError
```

### 함수 레벨 스코프와 블록 레벨 스코프

`var` 키워드로 선언한 변수는 **함수 레벨 스코프**를 따른다. 함수 몸체만 지역 스코프로 인정하고, `if`나 `for` 같은 코드 블록은 스코프로 보지 않는다. 그래서 블록 안에서 선언해도 블록 밖에서 그대로 참조된다.

```js
var x = 1;

if (true) {
  var x = 10; // 같은 전역 변수 x를 재할당한 것과 같다
}

console.log(x); // 10

for (var i = 0; i < 3; i++) {}
console.log(i); // 3: 반복문이 끝나도 i가 남는다
```

`let`과 `const`는 **블록 레벨 스코프**를 따른다. 함수뿐 아니라 모든 코드 블록이 지역 스코프가 되므로 블록 밖으로 변수가 새어 나가지 않는다.

```js
let y = 1;

if (true) {
  let y = 10; // 블록 안에서만 유효한 별개의 변수
  console.log(y); // 10
}

console.log(y); // 1

for (let j = 0; j < 3; j++) {}
// console.log(j); // ReferenceError
```

⇒ `var`의 함수 레벨 스코프는 의도치 않은 변수 중복 선언과 값 덮어쓰기를 만들기 쉽다. 특별한 이유가 없다면 `let` / `const`를 쓰는 편이 안전하다.

### 렉시컬 스코프

상위 스코프를 무엇으로 결정할지에 대해서는 두 가지 방식이 있다.

- **동적 스코프**: 함수를 **어디서 호출했는지**에 따라 상위 스코프를 결정한다.
- **렉시컬(정적) 스코프**: 함수를 **어디에 정의했는지**에 따라 상위 스코프를 결정한다.

자바스크립트는 렉시컬 스코프를 따른다.

```js
const x = 1;

function foo() {
  const x = 10;
  bar();
}

function bar() {
  console.log(x);
}

foo(); // 1
bar(); // 1
```

`bar`는 전역에서 정의됐으므로 상위 스코프는 언제나 전역 스코프다. `foo` 내부에서 호출하든 전역에서 호출하든 결과가 1로 같은 이유다. 만약 동적 스코프였다면 `foo()` 호출 시 10이 출력됐을 것이다.

함수의 상위 스코프는 **정의가 평가되는 시점**에 결정되어 함수 객체에 저장된다. 호출 위치는 이 값을 바꾸지 못한다. 이 성질이 이후에 배울 클로저의 토대가 된다.

### 스코프를 이해할 때 기억할 점


1. 식별자는 선언된 스코프 안에서만 사용할 수 있다.
2. 함수 내부에서는 자신이 속한 지역 스코프와 상위 스코프의 식별자를 사용할 수 있다.
3. 상위 스코프에서는 하위 스코프의 식별자를 사용할 수 없다.
4. 같은 이름이 있으면 현재 스코프의 식별자가 상위 스코프의 식별자보다 우선한다.
5. 스코프 체인은 함수가 정의될 때 결정되므로, 함수가 어디서 호출되는지는 변수 검색 순서를 바꾸지 않는다.


### 13장 핵심 흐름

```text
식별자 참조
  ↓
현재 스코프에서 검색 → 없으면 상위 스코프로
  ↓
상위 스코프는 "정의된 위치" 기준으로 이미 결정됨 (렉시컬 스코프)
  ↓
전역 스코프까지 없으면 ReferenceError
```

## 14장. 전역 변수의 문제점

### 변수의 생명 주기

지역 변수의 생명 주기는 함수의 생명 주기와 같다. 함수가 호출되면 지역 스코프(실행 컨텍스트)가 생성되면서 변수가 만들어지고, 함수가 종료되면 함께 소멸한다.

```js
function foo() {
  var x = 'local';
  console.log(x); // local
  return x;
}

foo();
// console.log(x); // ReferenceError: 함수 종료와 함께 소멸
```

호출될 때마다 스코프가 새로 생성되므로 이전 호출의 값이 남지 않는다.

```js
function counter() {
  var i = 0;
  i++;
  console.log(i);
}

counter(); // 1
counter(); // 1 — 매번 새로 생성된다
```

반면 `var`로 선언한 전역 변수의 생명 주기는 전역 객체의 생명 주기와 같다. 브라우저라면 페이지를 닫을 때까지, 즉 애플리케이션이 살아 있는 내내 메모리에 남는다.

### 전역 변수가 위험한 이유

1. **암묵적 결합** — 모든 코드가 전역 변수를 참조하고 변경할 수 있다. 즉, 코드 전체가 그 변수에 결합된다.
2. **긴 생명 주기** — 오래 살아 있는 만큼 값이 바뀔 기회도 많고, 메모리도 계속 점유한다.
3. **스코프 체인 종점에 위치** — 검색이 가장 마지막에 도달하는 위치라 조회 속도 면에서 가장 불리하다.
4. **네임스페이스 오염** — 파일이 분리돼 있어도 전역 스코프는 하나다. 다른 파일에서 같은 이름을 쓰면 서로 덮어쓴다.

```js
// a.js
var config = { mode: 'dev' };

// b.js — 같은 이름을 다시 선언해도 에러가 나지 않는다
var config = { mode: 'prod' }; // a.js의 값이 조용히 사라진다
```

### 암묵적 전역

선언 없이 값을 할당하면 자바스크립트 엔진이 전역 객체의 프로퍼티로 만들어 버린다.

```js
function foo() {
  bar = 10; // 선언 없이 할당
}

foo();
console.log(bar); // 10 — 전역에서 접근된다
```

`bar`는 변수 선언이 없었으므로 호이스팅되지 않고, 변수가 아니라 전역 객체의 프로퍼티이기 때문에 `delete`로 삭제까지 된다. 의도치 않은 전역 오염의 대표적인 원인이라, `strict mode`에서는 이 코드가 `ReferenceError`가 된다.

### 전역 변수 사용을 억제하는 방법

**즉시 실행 함수(IIFE)** — 모든 코드를 즉시 실행 함수로 감싸면 그 안의 변수는 함수의 지역 변수가 된다.

```js
(function () {
  var count = 0; // 지역 변수
  // ...
})();

// console.log(count); // ReferenceError
```

**네임스페이스 객체** — 전역에 객체 하나만 만들고 그 프로퍼티로 관리한다. 전역 변수 개수는 줄지만, 그 객체 자체는 여전히 전역이다.

```js
var MYAPP = {};
MYAPP.user = { name: 'Lee' };
console.log(MYAPP.user.name); // Lee
```

**모듈 패턴** — 즉시 실행 함수와 클로저를 이용해 공개할 것만 반환한다. 캡슐화와 정보 은닉이 가능하다.

```js
var Counter = (function () {
  var count = 0; // private

  return {
    increase() {
      return ++count;
    },
    decrease() {
      return --count;
    },
  };
})();

console.log(Counter.count); // undefined — 외부에서 직접 접근 불가
console.log(Counter.increase()); // 1
console.log(Counter.increase()); // 2
```

**ES6 모듈** — 파일 자체가 독립적인 모듈 스코프를 가진다. 모듈 안의 `var`는 전역 변수가 아니고, 전역 객체의 프로퍼티도 되지 않는다. 현재로서는 가장 근본적인 해결책이다.

```html
<script type="module" src="app.mjs"></script>
```

```text
       ├─ 즉시 실행 함수: 지역 스코프로 격리

       └─ ES6 모듈: 파일 단위 모듈 스코프 (권장)
```
