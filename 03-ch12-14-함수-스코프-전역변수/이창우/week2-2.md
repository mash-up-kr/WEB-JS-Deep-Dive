# 모던 자바스크립트 Deep Dive 4~7장 정리

변수, 표현식, 데이터 타입, 연산자 중심의 기본 문법 정리

## 4장. 변수

### 변수와 식별자

- **변수**: 값을 저장하기 위해 확보한 메모리 공간 또는 해당 공간의 이름
- **식별자**: 값 자체가 아닌 값의 위치를 찾기 위한 이름
- **할당**: 변수에 값 저장
- **참조**: 변수에 저장된 값 읽기

```js
const score = 80;
```

- `score`: 식별자
- `80`: 값

### 변수 선언

- **선언**: 변수 이름을 실행 컨텍스트에 등록
- **초기화**: 메모리 공간 확보와 초기값 할당

`var` 선언은 선언과 초기화가 함께 진행된다.

```js
var score;
console.log(score); // undefined
```

선언하지 않은 식별자에 접근하면 `ReferenceError`가 발생한다.

```js
console.log(userName); // ReferenceError
```

### 호이스팅

코드 실행 전 선언문을 먼저 처리하는 자바스크립트 엔진의 평가 과정이다. 선언문이 코드 상단으로 이동한 것처럼 보이는 현상을 호이스팅이라 한다.

```js
console.log(score); // undefined
var score;

score = 80;
console.log(score); // 80
```

- 변수 선언: 런타임 이전 처리
- 값 할당: 런타임 처리
- 실제 선언문이 이동한 것이 아니라 평가 과정의 결과

### 선언 키워드와 네이밍

```js
const MAX_RETRY_COUNT = 3;
let currentPage = 1;
```

- 변경 없는 값: `const`
- 재할당이 필요한 값: `let`
- `var`: 함수 레벨 스코프와 호이스팅 특성으로 새 코드에서는 사용을 지양
- 변수·함수: `camelCase`
- 클래스·생성자 함수: `PascalCase`

## 5장. 표현식과 문

### 값과 리터럴

- **값**: 표현식의 평가 결과
- **리터럴**: 값을 만들기 위한 표기법

```js
10;
'hello';
true;
null;
[];
{};
function () {};
```

### 표현식

값으로 평가 가능한 코드다.

```js
10 + 20;
score;
user.name;
getUser();
```

- 리터럴 표현식: `10`, `'hello'`
- 식별자 표현식: `score`, `user.name`
- 연산자 표현식: `10 + 20`, `score === 80`
- 함수 호출 표현식: `getUser()`

### 문

프로그램을 구성하는 최소 실행 단위다.

```js
let score; // 변수 선언문
score = 80; // 할당문

if (score >= 60) {
  console.log('pass');
}
```

문에는 선언문, 할당문, 조건문, 반복문 등이 있다.

### 표현식인 문과 표현식이 아닌 문

할당문은 값으로 평가 가능한 표현식인 문이다.

```js
let score;
const result = (score = 100);

console.log(result); // 100
```

변수 선언문과 조건문은 값으로 평가할 수 없다.

```js
let score;

// const result = let userName; // SyntaxError
// const result = if (score > 60) {}; // SyntaxError
```

### 세미콜론 자동 삽입

- 세미콜론: 문의 종료 표시
- ASI(Automatic Semicolon Insertion): 세미콜론 자동 삽입 기능
- 줄바꿈 위치에 따라 의도와 다른 해석이 발생할 수 있음
- 블록으로 끝나는 `if`, `for`, 함수 선언문 뒤에는 세미콜론을 사용하지 않음

> 표현식은 값이 필요한 자리이고, 문은 실행 흐름을 구성한다.

## 6장. 데이터 타입

### 타입 구분

| 구분 | 타입 |
| --- | --- |
| 원시 타입 | `number`, `string`, `boolean`, `undefined`, `null`, `symbol`, `bigint` |
| 객체 타입 | 객체, 배열, 함수 등 |

`bigint`는 책 초판 이후 추가된 원시 타입이다.

### 숫자 타입

정수와 실수를 구분하지 않는 배정밀도 64비트 부동소수점 방식이다.

특별한 값으로 `Infinity`, `-Infinity`, `NaN`이 있다.

```js
1 === 1.0; // true
3 / 2; // 1.5

10 / 0; // Infinity
10 / -0; // -Infinity
1 * 'hello'; // NaN
```

부동소수점 계산에는 오차가 발생할 수 있다.

```js
0.1 + 0.2; // 0.30000000000000004
```

`NaN`은 자기 자신과도 일치하지 않는다.

```js
NaN === NaN; // false
Number.isNaN(NaN); // true
```

전역 `isNaN`은 인자를 숫자로 변환한 뒤 검사할 수 있으므로, `NaN` 검사에는 `Number.isNaN`을 사용한다.

### 문자열과 템플릿 리터럴

문자열은 변경 불가능한 원시 값이다. 템플릿 리터럴은 백틱으로 표현한다.

```js
const name = '창우';
const message = `안녕하세요, ${name}님`;
```

템플릿 리터럴은 멀티라인 문자열과 `${}`를 통한 표현식 삽입을 지원하며, 문자열 연결이 많을 때 `+`보다 가독성이 좋다.

### `undefined`와 `null`

- `undefined`: 값이 미할당된 상태
- `null`: 의도적인 값의 부재

```js
let selectedUser; // undefined
const deletedUser = null;
```

`null`을 할당한다고 즉시 메모리가 해제되는 것은 아니다. 참조가 끊긴 값이 가비지 컬렉션 대상이 되며, 실제 정리 시점은 엔진이 결정한다.

### `symbol`과 `bigint`

`symbol`은 중복되지 않는 유일한 값으로, 객체의 고유 프로퍼티 키에 사용한다.

```js
const key = Symbol('key');
const user = {
  [key]: 'value',
};
```

`bigint`는 안전한 정수 범위를 넘는 큰 정수에 사용한다.

```js
const max = Number.MAX_SAFE_INTEGER;
const largeNumber = 9_007_199_254_740_993n;
```

`bigint`와 `number`는 산술 연산을 혼합할 수 없으며, 큰 정수 계산이 필요한 경우에만 사용한다.

### 확인할 내용

- 값 할당 시 타입 결정 방식
- `undefined`와 `null`의 역할 구분
- 부동소수점 오차와 `NaN`
- 암묵적 타입 변환 발생 지점

## 7장. 연산자

### 산술 연산자

```js
10 + 3; // 13
10 - 3; // 7
10 * 3; // 30
10 / 3; // 3.333...
10 % 3; // 1
```

`+`는 문자열 연결에도 사용된다.

```js
'1' + 2; // '12'
1 + true; // 2
1 + null; // 1
1 + undefined; // NaN
```

- 암묵적 타입 변환은 의도하지 않은 결과를 만들 수 있음
- 타입 변환이 필요할 때는 `Number()`, `String()`, `Boolean()` 활용

```js
const quantity = Number(inputValue);
```

### 할당 연산자와 부수 효과

```js
let score = 10;

score += 5;
score -= 3;
```

부수 효과는 코드 실행 전후의 상태 변화다. 할당 연산자, 증감 연산자, `delete` 연산자가 대표적이다.

`++`, `--`는 반환 시점과 값 변경 시점을 혼동할 수 있으므로 주의한다.

```js
let index = 0;
index += 1;
```

### 비교 연산자

```js
5 === 5; // true
5 === '5'; // false
5 == '5'; // true
```

- `==`, `!=`: 비교 전 암묵적 타입 변환
- `===`, `!==`: 값과 타입을 동시에 비교
- 기본 비교에는 `===`, `!==` 사용

```js
0 == ''; // true
0 === ''; // false

Object.is(NaN, NaN); // true
Object.is(0, -0); // false
```

`Object.is`는 `NaN`, `-0` 같은 특수 값의 비교가 필요한 상황에서 사용한다.

### 논리 연산자와 단축 평가

```js
true && false; // false
true || false; // true
!true; // false

'cat' && 'dog'; // 'dog'
'cat' || 'dog'; // 'cat'
```

`&&`, `||`는 불리언 외 피연산자의 값을 반환할 수 있다. 단축 평가는 결과가 확정되면 이후 표현식을 평가하지 않는다.

### `||`와 `??`

```js
const count = 0;

count || 10; // 10
count ?? 10; // 0
```

- `||`: falsy 값(`0`, `false`, `''`, `null`, `undefined`)이면 기본값 사용
- `??`: `null`, `undefined`일 때만 기본값 사용
- `0`, 빈 문자열, `false`를 유지해야 하면 `??` 사용

### 우선순위

우선순위가 한눈에 들어오지 않는 식에는 괄호를 사용한다.

```js
10 * 2 + 3; // 23
10 * (2 + 3); // 50
```

## 12장. 함수

### 함수의 역할

함수는 입력을 받아 출력을 내보내는 일련의 과정이다. 자바스크립트의 클로저, 실행 컨텍스트, 객체 생성, 메서드, `this`, 프로토타입, 모듈화 같은 주요 개념은 함수와 밀접하게 연결된다.

자바스크립트에서 함수는 함수 리터럴로 생성되는 객체다. 일반 객체는 호출할 수 없지만 함수 객체는 호출할 수 있으며, 값처럼 변수에 할당하거나 프로퍼티·배열 요소로 사용할 수 있는 일급 객체다.

## 함수 정의 방식

### 함수 선언문

```js
function add(x, y) {
  return x + y;
}

add(2, 5); // 7
```

함수 선언문은 표현식이 아닌 문이지만, 함수 이름과 같은 식별자를 자바스크립트 엔진이 암묵적으로 만들어 함수 객체를 연결한다. 따라서 함수 이름이 아니라 식별자를 통해 함수를 호출한다.

```js
function foo() {
  console.log('foo');
}

foo(); // foo
```

함수 이름은 함수 몸체 내부에서 유효한 식별자이고, 외부에서는 엔진이 만든 식별자를 사용한다.

### 함수 표현식

```js
const add = function (x, y) {
  return x + y;
};

add(2, 5); // 7
```

함수 리터럴은 문맥에 따라 함수 선언문 또는 함수 표현식으로 해석된다.

```js
function foo() {
  console.log('foo');
}

(function bar() {
  console.log('bar');
});

foo(); // foo
// bar(); // ReferenceError: 함수 표현식의 이름 bar는 외부 식별자가 아님
```

`{}`가 코드 블록 또는 객체 리터럴로 해석될 수 있는 것처럼, 함수 리터럴도 단독으로 사용하면 선언문으로, 값이 필요한 문맥에서 사용하면 표현식으로 해석된다.

### 화살표 함수

```js
const add = (x, y) => x + y;
```

화살표 함수는 함수를 간결하게 정의하는 ES6 문법이다. 일반 함수와 `this` 바인딩, `prototype` 프로퍼티, `arguments` 객체 등의 동작이 다르므로 단순한 문법 축약으로만 이해하면 안 된다.

### 함수 정의 방식 비교

| 방식 | 특징 | 선언 전 접근 |
| --- | --- | --- |
| 함수 선언문 | 이름이 있는 함수를 선언하고 함수 객체를 즉시 연결 | 가능 |
| 함수 표현식 | 함수 객체를 만든 뒤 변수에 할당 | 할당 전에는 불가 |
| 화살표 함수 | 익명 함수를 간결하게 표현하며 일반 함수와 `this` 동작이 다름 | 할당 전에는 불가 |

함수의 동작 자체보다 **언제 생성되고 어떤 식별자로 접근하는지**가 세 방식의 주요 차이다.

## 함수 생성 시점과 호이스팅

함수 선언문과 함수 표현식은 생성·할당 시점이 다르다.

```js
console.log(add(2, 5)); // 7
// console.log(sub(2, 5)); // TypeError: sub는 undefined

function add(x, y) {
  return x + y;
}

var sub = function (x, y) {
  return x - y;
};
```

자바스크립트 엔진은 런타임 전에 선언을 처리한다.

| 정의 방식 | 런타임 전 식별자 상태 | 선언 전 호출 |
| --- | --- | --- |
| 함수 선언문 | 함수 객체가 연결됨 | 가능 |
| `var` 함수 표현식 | `undefined`로 초기화됨 | 불가 (`TypeError`) |
| `let`·`const` 함수 표현식 | 초기화 전 상태(TDZ) | 불가 (`ReferenceError`) |

함수 호이스팅은 함수 객체가 연결된 상태까지 준비한다는 점에서 `var` 변수 호이스팅과 다르다.

## 함수 호출

### 매개변수와 인수

함수를 호출하면 함수 실행 컨텍스트가 생성되고, 매개변수 바인딩이 함수 실행 환경에 만들어진다. 전달된 인수는 매개변수에 순서대로 연결되며, 대응하는 인수가 없으면 `undefined`가 된다.

```js
function add(a, b) {
  const result = a + b;
  return result;
}

add(10, 20); // 30
add(10); // NaN (b는 undefined)
```

실행 흐름은 다음과 같이 이해하면 된다.

```text
함수 호출
  ↓
함수 실행 컨텍스트 생성
  ↓
매개변수 바인딩 생성 및 인수 연결
  ↓
함수 본문 실행
  ↓
반환값 전달
```

명세의 세부 초기화 단계를 모두 외우기보다는, “호출 시 실행 컨텍스트에 매개변수가 바인딩되고, 인수가 없으면 `undefined`가 된다”로 이해하는 것이 실용적이다.

매개변수 개수에는 문법상 제한이 없지만, 함수는 하나의 일을 하도록 만들고 매개변수는 적게 유지하는 편이 의도를 파악하기 쉽다.

## 참조에 의한 전달과 외부 상태 변경

자바스크립트의 인수 전달은 항상 값에 의한 전달이다. 다만 객체 값에는 객체를 가리키는 참조가 들어 있으므로, 객체를 전달하면 같은 객체를 가리키는 참조 값이 복사된다.

```js
function changeScore(user) {
  user.score = 100;
}

const user = { score: 0 };
changeScore(user);
console.log(user.score); // 100
```

원시 값은 값 자체가 복사되므로 외부 변수에 영향을 주지 않지만, 객체는 내부 프로퍼티를 변경하면 외부 상태도 바뀐다. 이런 부수 효과는 추적하기 어려운 원인이 될 수 있다.

필요하다면 객체를 직접 변경하지 말고 복사본을 만들어 반환한다.

```js
function changeScore(user) {
  return { ...user, score: 100 };
}

const user = { score: 0 };
const changedUser = changeScore(user);
```

## 콜백 함수와 고차 함수

콜백 함수는 함수의 매개변수를 통해 다른 함수 내부로 전달되어 특정 시점에 호출되는 함수다. 콜백을 전달받아 실행하는 함수를 고차 함수라고 한다.

```js
function repeat(count, callback) {
  for (let i = 0; i < count; i += 1) {
    callback(i);
  }
}

repeat(3, (index) => console.log(index)); // 0, 1, 2
```

변하지 않는 공통 로직은 고차 함수에 두고, 달라지는 동작은 콜백으로 전달하면 로직을 재사용할 수 있다. 이벤트 리스너, 배열 메서드의 인수 등이 대표적인 활용 사례다.

## 순수 함수와 비순수 함수

| 구분 | 특징 |
| --- | --- |
| 순수 함수 | 같은 인수에 항상 같은 값을 반환하고 외부 상태를 읽거나 변경하지 않음 |
| 비순수 함수 | 외부 상태에 의존하거나 외부 상태를 변경함 |

```js
// 순수 함수
function add(a, b) {
  return a + b;
}

// 비순수 함수: 외부 변수 변경
let total = 0;
function increase(value) {
  total += value;
}
```

순수 함수는 결과를 예측하기 쉽고 테스트와 재사용에 유리하다. 객체를 다룰 때는 원본을 변경하지 않는 불변 처리 방식을 우선 고려한다.

### 12장 핵심 흐름

```text
함수 정의
  ├─ 선언문: 함수 호이스팅으로 선언 전 호출 가능
  ├─ 표현식: 변수 할당 이후 호출 가능
  └─ 화살표 함수: 간결한 문법, 일반 함수와 다른 this 동작
       ↓
함수 호출 → 실행 컨텍스트와 매개변수 생성
       ↓
인수 전달 → 원시 값은 값 복사, 객체는 참조 값 복사
       ↓
콜백 전달 → 공통 로직과 변경 로직 분리
       ↓
순수 함수 지향 → 외부 상태 변경 최소화
```

## 스코프와 스코프 체인

### 스코프란?

스코프는 **식별자가 유효한 범위**다. 변수나 함수의 이름을 어디까지 사용할 수 있는지를 결정하며, 같은 이름이 여러 개 있을 때 어떤 식별자를 참조할지도 결정한다. 이 과정을 식별자 결정이라고 한다.

```js
const x = '전역';

function outer() {
  const x = '지역';
  console.log(x); // 지역: 가장 가까운 지역 스코프의 x
}

outer();
console.log(x); // 전역
```

스코프는 함수를 호출한 위치가 아니라 함수를 **어디에 정의했는지**를 기준으로 결정된다. 코드가 작성된 위치와 주변 코드의 관계를 렉시컬 환경이라고 하며, 실행 컨텍스트는 이 환경을 바탕으로 코드를 평가하고 실행한다.

### 전역 스코프와 지역 스코프

- **전역 스코프**: 코드의 가장 바깥 영역. 전역 변수는 프로그램 어디서든 접근할 수 있다.
- **지역 스코프**: 함수 내부처럼 특정 영역에 생성되는 스코프. 지역 변수는 해당 스코프와 하위 스코프에서만 접근할 수 있다.

```js
const globalValue = '전역';

function showValue() {
  const localValue = '지역';
  console.log(globalValue); // 전역 변수 접근 가능
  console.log(localValue); // 지역 변수 접근 가능
}

showValue();
// console.log(localValue); // ReferenceError: 함수 밖에서는 접근 불가
```

### 스코프 체인

함수가 중첩되면 스코프도 계층적인 구조를 이룬다. 이 연결을 스코프 체인이라고 한다.

```js
const x = '전역';

function outer() {
  const y = 'outer';

  function inner() {
    const z = 'inner';
    console.log(z); // inner: 현재 스코프에서 찾음
    console.log(y); // outer: 상위 스코프에서 찾음
    console.log(x); // 전역: 계속 상위로 이동해 찾음
  }

  inner();
}

outer();
```

변수를 참조할 때 자바스크립트 엔진은 현재 스코프에서 검색을 시작한다. 찾지 못하면 상위 스코프로 이동하며, 전역 스코프까지 검색한 뒤에도 없으면 `ReferenceError`를 발생시킨다. 하위 스코프가 상위 스코프의 변수에 접근할 수 있는 이유도 이 검색 규칙 때문이다.

```text
inner 스코프
  ↓ 없으면
outer 스코프
  ↓ 없으면
전역 스코프
  ↓ 그래도 없으면
ReferenceError
```

### 스코프를 이해할 때 기억할 점

1. 식별자는 선언된 스코프 안에서만 사용할 수 있다.
2. 함수 내부에서는 자신이 속한 지역 스코프와 상위 스코프의 식별자를 사용할 수 있다.
3. 상위 스코프에서는 하위 스코프의 식별자를 사용할 수 없다.
4. 같은 이름이 있으면 현재 스코프의 식별자가 상위 스코프의 식별자보다 우선한다.
5. 스코프 체인은 함수가 정의될 때 결정되므로, 함수가 어디서 호출되는지는 변수 검색 순서를 바꾸지 않는다.
