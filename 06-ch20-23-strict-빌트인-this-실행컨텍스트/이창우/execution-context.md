# 모던 자바스크립트 Deep Dive 23장 정리

> 실행 컨텍스트

## 소스코드의 타입

ECMAScript 사양은 실행 가능한 코드를 네 가지 타입으로 나눈다. 코드의 타입에 따라 실행 컨텍스트를 생성하는 과정과 관리하는 내용이 다르다.

| 소스코드 타입 | 설명 |
| --- | --- |
| 전역 코드 | 전역에 존재하는 소스코드. 함수와 클래스 내부 코드는 제외한다. |
| 함수 코드 | 함수 내부에 존재하는 소스코드. 중첩 함수와 클래스 내부 코드는 제외한다. |
| `eval` 코드 | 빌트인 전역 함수 `eval`에 문자열로 전달된 소스코드 |
| 모듈 코드 | 모듈 내부의 소스코드. 모듈별로 독립적인 모듈 스코프를 만든다. |

## 평가와 실행

자바스크립트 엔진은 소스코드를 바로 실행하지 않고 **소스코드 평가**와 **소스코드 실행** 과정으로 나누어 처리한다.

**평가 과정**에서는 실행 컨텍스트를 생성하고, 변수·함수 등의 **선언문만 먼저 실행**하여 식별자를 키로 실행 컨텍스트가 관리하는 스코프에 등록한다.

**실행 과정**에서는 선언문을 제외한 코드를 위에서부터 순차적으로 실행한다. 이때 필요한 값은 실행 컨텍스트가 관리하는 스코프에서 검색하고, 실행 결과는 다시 같은 스코프에 반영한다.

```js
var x;
x = 1;
```

```text
평가: var x; → x를 등록하고 undefined로 초기화
실행: x = 1; → x를 검색한 뒤 1을 할당
```

호이스팅은 선언문이 물리적으로 위로 이동하는 현상이 아니라, 이 평가 과정의 결과다.

## 실행 컨텍스트가 필요한 이유

코드를 실행하려면 식별자와 스코프뿐만 아니라 현재 실행 중인 코드와 돌아갈 위치까지 관리해야 한다.

1. 선언에 의해 생성된 식별자를 스코프별로 등록하고, 바인딩된 값의 변화를 관리해야 한다.
2. 스코프의 중첩 관계를 스코프 체인으로 형성하고, 상위 스코프로 이동하며 식별자를 검색할 수 있어야 한다.
3. 함수 호출로 실행 순서가 바뀌면 새 코드를 실행하다가, 호출이 끝난 뒤 이전 코드로 돌아가야 한다.

**실행 컨텍스트**는 소스코드를 실행하는 데 필요한 환경을 제공하고, 코드의 실행 결과를 관리하는 영역이다.

- **식별자와 스코프**: 렉시컬 환경으로 관리
- **코드 실행 순서**: 실행 컨텍스트 스택으로 관리

## 실행 컨텍스트 스택

실행 컨텍스트 스택은 생성된 실행 컨텍스트를 스택 자료구조로 관리한다. 코드가 호출되면 새 실행 컨텍스트가 푸시되고, 실행을 마치면 팝된다.

```js
const x = 1;

function foo() {
  const y = 2;

  function bar() {
    const z = 3;
    console.log(x + y + z);
  }

  bar();
}

foo();
```

```text
1. 전역 코드 실행

   ┌──────────────┐
   │ 전역 실행 컨텍스트 │ ← 실행 중인 실행 컨텍스트
   └──────────────┘

2. foo 호출

   ┌──────────────┐
   │ foo 함수 실행 컨텍스트 │ ← 실행 중인 실행 컨텍스트
   ├──────────────┤
   │ 전역 실행 컨텍스트     │
   └──────────────┘

3. bar 호출

   ┌──────────────┐
   │ bar 함수 실행 컨텍스트 │ ← 실행 중인 실행 컨텍스트
   ├──────────────┤
   │ foo 함수 실행 컨텍스트 │
   ├──────────────┤
   │ 전역 실행 컨텍스트     │
   └──────────────┘

4. bar 종료 → bar 컨텍스트 팝 → foo로 복귀
5. foo 종료 → foo 컨텍스트 팝 → 전역 코드로 복귀
```

스택 최상위의 실행 컨텍스트가 항상 **실행 중인 실행 컨텍스트**다. 이 예제에서는 `전역 → foo → bar → foo → 전역`으로 실행의 포커스가 이동한다.

## 렉시컬 환경

렉시컬 환경은 **식별자와 식별자에 바인딩된 값, 상위 스코프에 대한 참조**를 기록하는 자료구조다. 실행 컨텍스트를 구성하며, 키와 값을 갖는 객체 형태의 스코프로 이해할 수 있다.

```text
렉시컬 환경
├─ 환경 레코드
│    └─ 현재 스코프의 식별자와 바인딩된 값 관리
└─ 외부 렉시컬 환경에 대한 참조
     └─ 상위 스코프의 렉시컬 환경을 가리킴
```

### 환경 레코드

환경 레코드는 스코프에 포함된 식별자를 등록하고, 각 식별자에 바인딩된 값을 관리하는 저장소다. 전역 코드와 함수 코드처럼 소스코드의 타입에 따라 사용하는 환경 레코드와 관리 방식이 달라진다.

### 외부 렉시컬 환경에 대한 참조

현재 평가 중인 소스코드를 포함하는 상위 코드의 렉시컬 환경을 가리킨다. 이 참조가 렉시컬 환경을 단방향으로 연결하여 **스코프 체인**을 구현한다.

```text
bar 렉시컬 환경
  → foo 렉시컬 환경
    → 전역 렉시컬 환경
      → null
```

실행 컨텍스트는 렉시컬 환경과 변수 환경을 컴포넌트로 갖는다. 두 컴포넌트는 실행 컨텍스트가 생성될 때 같은 렉시컬 환경을 참조한다. 다만 블록 스코프처럼 새 렉시컬 환경이 추가되면 둘의 참조가 일시적으로 달라질 수 있다.

```text
실행 컨텍스트
├─ LexicalEnvironment  ─┐
│                       ├─ 초기에는 같은 렉시컬 환경을 참조
└─ VariableEnvironment ─┘
```

## 전역 코드 평가

소스코드가 로드되면 자바스크립트 엔진은 전역 코드를 평가한다.

```text
1. 전역 실행 컨텍스트 생성
2. 전역 렉시컬 환경 생성
   2.1. 전역 환경 레코드 생성
        - 객체 환경 레코드 생성
        - 선언적 환경 레코드 생성
   2.2. this 바인딩
   2.3. 외부 렉시컬 환경에 대한 참조 결정
```

### 1. 전역 실행 컨텍스트 생성

빈 전역 실행 컨텍스트를 생성해 실행 컨텍스트 스택에 푸시한다. 이때부터 전역 실행 컨텍스트가 실행 중인 실행 컨텍스트가 된다.

### 2. 전역 렉시컬 환경 생성

전역 렉시컬 환경을 생성한 뒤 전역 실행 컨텍스트에 바인딩한다. 전역 렉시컬 환경의 환경 레코드는 **전역 환경 레코드**다.

```text
전역 렉시컬 환경
├─ 전역 환경 레코드
│  ├─ 객체 환경 레코드
│  └─ 선언적 환경 레코드
└─ 외부 렉시컬 환경에 대한 참조: null
```

#### 객체 환경 레코드

`var`로 선언한 전역 변수와 함수 선언문으로 정의한 전역 함수를 관리한다. 객체 환경 레코드는 `BindingObject`라는 객체와 연결되며, 전역 환경에서의 `BindingObject`는 전역 객체다.

```js
var x = 1;

function foo() {}

console.log(window.x); // 1
console.log(window.foo === foo); // true
```

전역 객체는 전역 코드를 평가하기 전에 이미 생성된다. 브라우저에서는 표준 빌트인 객체와 전역 함수, Web API 같은 호스트 객체가 `window`에 추가된다. 객체 환경 레코드는 이미 존재하는 전역 객체를 새로 만드는 것이 아니라, `BindingObject`를 통해 그 객체와 `var` 변수·함수 선언을 연결한다.

평가 시점의 선언 처리 방식에 따라 `var` 변수와 함수 선언문의 호이스팅 결과가 다르다.

```js
console.log(x); // undefined
console.log(foo()); // 'function'

var x = 1;

function foo() {
  return 'function';
}
```

- `var x = 1`: 평가 시 `x`를 등록하고 `undefined`로 초기화한다. `1`은 실행 단계에서 할당한다.
- `function foo() {}`: 평가 시 `foo`를 등록하고 생성된 함수 객체까지 바인딩한다.

그래서 `var` 변수는 선언 전에 `undefined`로 참조할 수 있지만, 함수 선언문으로 정의한 함수는 선언 전에도 바로 호출할 수 있다.

#### 선언적 환경 레코드

`let`, `const`, `class`로 선언한 전역 식별자를 관리한다. 이 바인딩들은 전역 객체의 프로퍼티가 아닌 선언적 환경 레코드의 개념적인 블록 내에 존재한다.

```js
let y = 2;
const z = 3;

console.log(window.y); // undefined
console.log(window.z); // undefined
```

`let`과 `const`도 평가 과정에서 호이스팅된다. 다만 선언과 초기화가 분리되어 실행 과정에서 선언문에 도달하기 전까지 초기화되지 않은 상태로 남는다. 이 구간이 **TDZ(Temporal Dead Zone)**다.

```js
// console.log(y); // ReferenceError: Cannot access 'y' before initialization
let y = 2;
```

이때의 `ReferenceError`는 `y`가 없어서가 아니라, 렉시컬 환경에 등록되었지만 아직 초기화되지 않았기 때문이다.

#### this 바인딩과 외부 참조

전역 환경 레코드는 `[[GlobalThisValue]]` 내부 슬롯에 전역 `this`가 참조할 값을 보관한다. 브라우저의 일반 스크립트 전역에서 `this`는 `window`를 가리킨다.

```js
console.log(this === window); // true (브라우저 일반 스크립트)
```

ES 모듈의 최상위 `this`는 `undefined`이므로 두 환경을 같게 보면 안 된다.

전역 렉시컬 환경은 소스코드의 최상위 스코프이므로 외부 렉시컬 환경에 대한 참조는 `null`이다.

## 전역 코드 실행

전역 코드 평가가 끝나면 선언문을 제외한 전역 코드를 순차적으로 실행한다. 식별자를 참조할 때는 현재 렉시컬 환경에서 검색을 시작한다.

```js
var x = 1;
let y = 2;

function foo() {
  console.log(x + y);
}

foo();
```

1. `x`는 전역 환경 레코드의 객체 환경 레코드에서 찾는다.
2. `y`는 전역 환경 레코드의 선언적 환경 레코드에서 찾는다.
3. `foo`는 객체 환경 레코드에 바인딩된 함수 객체를 호출한다.
4. `foo`가 호출되면 전역 코드의 실행을 일시 중단하고 함수 코드 평가를 시작한다.

스코프 체인의 종점인 전역 렉시컬 환경에서도 식별자를 찾지 못하면 `ReferenceError`가 발생한다.

## 함수 코드 평가

함수가 호출되면 전역 코드의 실행을 일시 중단하고 함수 내부로 코드의 제어권이 이동한다. 이후 함수 코드를 평가한다.

```text
1. 함수 실행 컨텍스트 생성
2. 함수 렉시컬 환경 생성
   2.1. 함수 환경 레코드 생성
   2.2. this 바인딩
   2.3. 외부 렉시컬 환경에 대한 참조 결정
```

### 1. 함수 실행 컨텍스트 생성

함수 실행 컨텍스트를 생성한다. 함수 렉시컬 환경의 구성을 마친 뒤 실행 컨텍스트 스택에 푸시하면 해당 함수 실행 컨텍스트가 실행 중인 실행 컨텍스트가 된다.

### 2. 함수 렉시컬 환경 생성

함수 렉시컬 환경을 생성하고 함수 실행 컨텍스트에 바인딩한다.

#### 함수 환경 레코드

함수 환경 레코드는 매개변수, `arguments` 객체, 함수 내부의 지역 변수와 중첩 함수 등을 등록하고 관리한다.

```js
function foo(a) {
  var x = 1;
  const y = 2;

  function bar() {}
}

foo(10);
```

`foo(10)`을 호출하면 `a`, `arguments`, `x`, `y`, `bar`가 `foo` 함수의 렉시컬 환경에서 관리된다. 다만 `const y`와 같은 렉시컬 선언의 정확한 초기화 시점은 `var x`와 다르다.

#### this 바인딩

함수 환경 레코드의 `[[ThisValue]]` 내부 슬롯에 `this`가 바인딩된다. 어떤 값이 바인딩되는지는 22장에서 본 것처럼 **함수 호출 방식**에 따라 결정된다.

```js
function foo() {
  console.log(this);
}

foo(); // 일반 함수 호출: window, strict mode에서는 undefined
```

화살표 함수는 자신만의 `this` 바인딩을 만들지 않고 상위 스코프의 `this`를 렉시컬하게 참조한다.

#### 외부 렉시컬 환경에 대한 참조 결정

자바스크립트는 함수를 **어디서 호출했는지가 아니라 어디에 정의했는지**에 따라 상위 스코프를 결정한다. 이를 렉시컬 스코프라 한다.

함수 정의가 평가되어 함수 객체를 생성할 때, 현재 실행 중인 실행 컨텍스트의 렉시컬 환경을 함수 객체의 `[[Environment]]` 내부 슬롯에 저장한다. 함수가 호출되면 저장해 둔 참조가 새 함수 렉시컬 환경의 외부 참조가 된다.

```js
const x = 1;

function foo() {
  const x = 10;
  bar(); // bar를 foo 내부에서 호출
}

function bar() {
  console.log(x); // bar는 전역에서 정의됨
}

foo(); // 1
```

`bar`는 `foo` 안에서 호출되었지만 전역에서 정의되었다. 따라서 `bar`의 외부 렉시컬 환경 참조는 `foo`가 아니라 전역 렉시컬 환경을 가리키고, `x`는 `1`이다. 함수가 정의될 때 저장한 상위 렉시컬 환경은 클로저를 이해하는 핵심 단서다.

## 함수 코드 실행과 식별자 검색

함수 코드 평가가 끝나면 함수 코드를 순차적으로 실행한다. 아래 코드에서 `bar`가 `console.log` 표현식을 실행하는 과정을 보자.

```js
const x = 1;

function foo(a) {
  const y = 2;

  function bar(b) {
    const z = 3;
    console.log(a + b + x + y + z);
  }

  bar(4);
}

foo(5); // 15
```

```text
bar 렉시컬 환경: b = 4, z = 3
  ↓ 없으면 외부 참조로 이동
foo 렉시컬 환경: a = 5, y = 2, bar
  ↓ 없으면 외부 참조로 이동
전역 렉시컬 환경: x = 1, foo, console
  ↓ 여기에서도 없으면
ReferenceError
```

- `b`, `z`: `bar`의 환경 레코드에서 검색
- `a`, `y`: `bar`에는 없으므로 외부 참조가 가리키는 `foo`에서 검색
- `x`, `console`: `foo`에도 없으므로 전역 렉시컬 환경에서 검색

브라우저에서 `console`은 전역 객체의 프로퍼티이므로 전역 렉시컬 환경의 객체 환경 레코드가 연결한 `BindingObject`, 즉 `window`에서 찾는다. 이후 `console`의 `log` 프로퍼티를 검색해 함수를 호출한다.

`bar`의 실행이 끝나면 `bar` 실행 컨텍스트를 스택에서 팝하고 `foo`로 돌아간다. `foo`도 종료되면 전역 실행 컨텍스트로 돌아간다.

## 블록 렉시컬 환경

`if`, `for`, `while`, `try/catch` 등의 코드 블록에 `let`, `const`, `class` 선언이 있으면 그 블록만의 렉시컬 환경이 생성된다.

```js
let x = 1;

if (true) {
  let x = 10;
  console.log(x); // 10
}

console.log(x); // 1
```

```text
if 블록 진입
LexicalEnvironment → 블록 렉시컬 환경 → 이전 렉시컬 환경
VariableEnvironment → 이전 렉시컬 환경

if 블록 종료
LexicalEnvironment → 이전 렉시컬 환경으로 복귀
```

이 과정에서 렉시컬 환경과 변수 환경이 처음에는 같은 렉시컬 환경을 참조하지만 새 블록 스코프에 진입하면 달라질 수 있다는 점이 드러난다.

`for` 문에 `let`을 사용하면 반복할 때마다 독립적인 렉시컬 환경을 생성한다. 이로 인해 클로저가 각 반복 시점의 변수를 기억할 수 있다.

```js
const funcs = [];

for (let i = 0; i < 3; i += 1) {
  funcs.push(() => i);
}

console.log(funcs[0]()); // 0
console.log(funcs[1]()); // 1
console.log(funcs[2]()); // 2
```

## 전체 흐름

```text
전역 객체 생성
  ↓
전역 코드 평가
  ├─ 전역 실행 컨텍스트 생성
  ├─ 전역 렉시컬 환경 생성
  └─ 식별자 등록·초기화
  ↓
전역 코드 실행
  ├─ 값 할당·참조
  └─ 함수 호출
       ↓
     함수 코드 평가
       ├─ 함수 실행 컨텍스트 생성
       ├─ 함수 렉시컬 환경 생성
       ├─ 매개변수·지역 선언 등록
       ├─ this 바인딩
       └─ 외부 렉시컬 환경 참조 결정
       ↓
     함수 코드 실행
       ├─ 필요한 식별자를 스코프 체인으로 검색
       └─ 종료 시 함수 실행 컨텍스트 팝
  ↓
이전 실행 컨텍스트로 복귀
```

## 23장 핵심 정리

- 소스코드는 **평가**와 **실행** 과정으로 나누어 처리된다.
- 실행 컨텍스트는 코드 실행에 필요한 환경과 실행 결과를 관리한다.
- 렉시컬 환경의 **환경 레코드**는 식별자와 값을, **외부 렉시컬 환경 참조**는 상위 스코프를 관리한다.
- 전역 환경 레코드는 `var`·함수 선언을 담는 **객체 환경 레코드**와 `let`·`const`·`class`를 담는 **선언적 환경 레코드**로 나뉘다.
- 함수는 정의될 때의 렉시컬 환경을 `[[Environment]]`에 저장하고, 호출될 때 이를 외부 렉시컬 환경 참조로 사용한다.
- 실행 컨텍스트 스택은 현재 실행 중인 코드와 종료 후 돌아갈 코드의 순서를 관리한다.
- 식별자 검색은 현재 렉시컬 환경에서 시작해 외부 참조를 따라 전역 렉시컬 환경까지 이동한다.
